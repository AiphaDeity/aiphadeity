空调会根据温度调节运行状态，路由器会接收并转发网络数据，智能手表会记录运动信息。这些设备功能各异，却都需要内部的计算与控制能力。

学习嵌入式时，我们很快会遇到 MCU、FPGA、寄存器、RTOS 等名词。如果还不知道它们分别回答什么问题，就容易把一串词记住，却看不清一台设备是怎样工作的。本文先建立整体认识，具体的电路和程序配置留给后面的文章。

## 一、先从身边的设备说起

先看一台空调。温度传感器提供环境信息，控制部分比较当前温度与设定值，再决定如何控制相关部件。负责这些任务的计算系统，是空调的一部分。

> **嵌入式系统是融入设备或更大系统、为特定任务提供计算与控制能力的系统，通常由硬件和软件共同构成。**

“特定任务”不等于“只能做一件事”。路由器既要处理网络数据，也可能提供设置界面；智能手表可能同时采集传感器数据、显示信息并与手机通信。它们的功能不一样，但计算系统都是围绕设备的用途设计的。

### 1.1 芯片、开发板和产品有什么区别？

| 对象 | 可以怎样理解 | 还缺什么 |
| --- | --- | --- |
| 芯片 | 提供处理、存储或其他功能的器件 | 通常需要供电、连接及外围电路 |
| 开发板 | 把芯片与部分电路、接口组合起来，方便学习和验证 | 不一定具备产品需要的结构与可靠性 |
| 产品 | 为实际使用场景设计的完整设备 | 需要满足功能之外的成本、功耗等要求 |

例如，能在开发板上点亮 LED，说明我们完成了一个小实验；要做成长期工作的设备，还要考虑供电、环境和故障处理。这三个对象彼此相关，但不能直接画等号。

## 二、嵌入式在哪些地方使用？

日常交流中可以说“嵌入式行业”。从技术角度看，嵌入式更像一套**跨领域使用的方法与技术**：不同领域提出设备需求，嵌入式系统帮助设备实现感知、计算、控制和通信。

| 应用领域 | 常见任务示例 |
| --- | --- |
| 家电与消费电子 | 读取环境信息、控制运行状态 |
| 汽车电子 | 车身功能控制、仪表信息处理 |
| 工业与机器人 | 数据采集、运动控制 |
| 医疗设备 | 监测设备中的信号采集与处理 |
| 通信设备 | 接收、处理和转发数据 |

这些例子说明的是应用范围，不代表同一套方案能够直接用于所有产品。设备的成本、功耗、安全性和可靠性要求不同，实现方式也会不同。

**一句话概括：行业决定设备要解决什么问题，嵌入式技术帮助设备把功能做出来。**

## 三、一个嵌入式系统怎样工作？

先从最简单的实验理解：**按下按键 → 程序读取按键状态并判断 → LED 改变状态**。这可以概括为“输入 → 处理 → 输出”。

| 环节 | 按键与 LED 实验 | 在其他设备中还可能是什么 |
| --- | --- | --- |
| 输入 | 按键状态 | 传感器信号、通信数据 |
| 处理 | 程序判断是否按下 | 计算、判断、状态更新 |
| 输出 | 改变 LED 状态 | 更新显示、发送数据、控制驱动电路 |

### 3.1 从光照变化到电脑显示

再把这个模型放到一个稍完整的例子中：采集光照变化，并在电脑上显示结果。

  <figcaption>光照采集到电脑显示的过程</figcaption>
  <ol>
    <li><span>01 · 感知</span><strong>光照变化</strong></li>
    <li><span>02 · 转换</span><strong>光敏电阻与分压电路</strong><small>产生变化的电压</small></li>
    <li><span>03 · 采样</span><strong>ADC</strong><small>把电压转换成数字量</small></li>
    <li><span>04 · 处理</span><strong>MCU 运行程序</strong><small>处理采样结果</small></li>
    <li><span>05 · 发送</span><strong>UART 与适配接口</strong><small>经 USB 转串口等接口传输</small></li>
    <li><span>06 · 显示</span><strong>电脑显示结果</strong></li>
  </ol>
</figure>

光敏电阻的阻值随光照变化；它配合分压电路，才能形成可供采样的电压。**ADC**（模数转换器）把模拟电压转换为数字量，程序处理后通过 **UART** 串行通信接口发送。如果电脑通过 USB 接收，通常还需要 USB 转串口等适配环节。

这里显示的是采样结果。未经标定和换算，不能把 ADC 数值直接称为准确的照度。

“输入 → 处理 → 输出”是**理解行为的简化模型**。真实设备可能不断重复这一过程，也可能同时处理多个输入；空调还会根据控制后的温度变化继续调整运行状态。通信数据既可以是输入，也可以是输出。

## 四、系统由什么组成？

上面讲的是设备**做了什么**。要实现这些行为，还需要硬件与软件配合。

| 组成 | 提供什么 | 光照采集例子 |
| --- | --- | --- |
| 硬件 | 感知、计算、存储、通信等物理能力 | 光敏电阻、分压电路、处理芯片、通信接口、供电 |
| 软件 | 规定何时读取、怎样处理、何时输出 | 安排采样、处理数字量、发送结果 |

软件可以包含应用程序、驱动和软件库；有些设备还会运行操作系统。硬件提供能力，软件决定如何使用这些能力，两者并不是各做各的。

例如，程序能够产生控制信号，并不意味着芯片引脚可以直接带动电机。电机通常还需要合适的驱动电路和供电。

**输入、处理、输出描述系统行为；硬件、软件描述系统组成。** 它们是观察同一台设备的两个角度。

## 五、MCU、MPU 和 FPGA 分别在哪里？

处理平台是系统组成的一部分。初学阶段先认识几个常见名称，不必马上研究内部架构。

| 名称 | 入门时怎样理解 | 需要注意 |
| --- | --- | --- |
| CPU | 执行指令的处理核心 | 它不是与 MCU、MPU 并列的完整设备类别 |
| MCU（微控制器） | 通常在一颗芯片中集成处理核心、存储器和常用外设 | STM32 的微控制器系列是例子 |
| MPU（微处理器） | 常用于处理需求较复杂的系统，往往配合外部存储器 | 不等于“必须运行 Linux” |
| FPGA（现场可编程门阵列） | 可配置的逻辑器件，能按设计实现特定数字电路 | 可以与处理器协作，本身不等于完整系统 |

前面的光照采集实验，可以用具有合适 ADC 和通信接口的 MCU 实现。另一些设备可能选用 MPU，或者让 FPGA 承担特定的逻辑处理任务。处理器系统和可编程逻辑也可以集成在同一颗芯片中，例如 [AMD Zynq 7000](https://docs.amd.com/r/en-US/ug585-zynq-7000-SoC-TRM/Introduction?contentId=SjQeLB_~DOGhzWyHRNyyaQ)。

这是常见特征的概括，不是按性能排出的等级。MCU 不等于“只能写裸机程序”，MPU 不等于“必须使用 Linux”。具体器件还要根据任务、资源和设计约束选择。想核对基本定义，可以看 [ST 对 MCU 与 MPU 的介绍](https://www.st.com/en/microcontrollers-microprocessors.html)和 [Intel 对 FPGA 的说明](https://www.intel.com/content/www/us/en/docs/oneapi-fpga-add-on/developer-guide/2024-0/fpga-architecture-overview.html)。

> **缩写提醒：** 某些芯片文档里的 MPU 还可能指 *Memory Protection Unit*（内存保护单元）。本文讨论处理平台时，MPU 指微处理器。

## 六、寄存器、HAL、RTOS 和 Linux 怎么放在一起？

这些词经常同时出现在学习资料里，但它们回答的是**不同的问题**：

<dl class="article-concept-map">
  <div><dt>使用什么硬件？</dt><dd>MCU、MPU、FPGA，或它们的组合</dd></div>
  <div><dt>程序怎样组织和运行？</dt><dd>裸机、RTOS、嵌入式 Linux</dd></div>
  <div><dt>软件怎样访问外设？</dt><dd>直接操作寄存器，或使用厂商驱动库</dd></div>
</dl>

**裸机、RTOS、嵌入式 Linux** 主要涉及运行环境。裸机通常不运行操作系统，可以用主循环和中断组织程序；RTOS（实时操作系统）提供任务调度、同步等机制；嵌入式 Linux 则用于具备相应条件的设备，其开发还可分为系统、驱动和应用等层次。

**寄存器和厂商驱动库** 主要涉及访问硬件的方法。以 STM32 为例，可以直接配置外设寄存器，也可以使用 HAL、LL 等接口。HAL 是硬件抽象层，LL 更贴近硬件；它们不是操作系统。[ST 的 STM32Cube 软件包说明](https://www.st.com/en/embedded-software/stm32cube-mcu-mpu-packages.html)也将 HAL、LL 与 RTOS 作为不同组件列出。较早的标准外设库仍可能出现在旧项目和学习资料中，具体支持以对应芯片的软件包为准。

两类选择可以组合，例如“MCU + 裸机 + HAL”或“MCU + RTOS + HAL”。但用了 RTOS，不代表系统自动满足实时要求；实际效果仍要靠设计和验证。

**所以，不要把“寄存器 → HAL → RTOS → Linux”当成必须依次走完的升级路线。**

## 七、怎样判断一个设备里的“嵌入式部分”？

嵌入式通常强调计算能力为具体设备或功能服务，而不是让用户像使用通用电脑那样自由安装、运行各种程序。路由器、智能门锁、相机和工业控制器的用途差别很大，但都可能包含围绕专门任务设计的处理器、软件与外部电路。设备里面装了 Linux，不会因此自动变成普通台式电脑；用的是小 MCU，也不自动意味着设计简单。

有时一个产品同时包含多个计算部分：主处理器负责界面和网络，低功耗 MCU 负责按键、电源管理或传感器，FPGA 负责特定高速逻辑。讨论“它是不是嵌入式”时，先指出自己谈的是整个产品，还是其中承担特定任务的子系统，比争论某个芯片名词更有帮助。

开发板也要和最终产品区分。开发板为了学习和调试，常把接口、指示灯和调试器做得很方便；量产设备则要考虑体积、成本、供电、环境和维护。把示例程序烧进开发板，只是验证某个系统行为的起点，并不等于完成了产品设计。

## 八、回到一台真实设备

遇到一个新项目，可以先问四个问题：

1. **它要完成什么任务？** 输入是什么，期望输出是什么？
2. **需要哪些硬件？** 信号从哪里来，由什么器件处理，怎样作用于外界？
3. **软件怎样组织？** 简单主循环是否够用，是否需要任务或更完整的系统？
4. **如何验证？** 每一环是否都能观察和检查？

回到光照采集的例子：任务是把光照变化显示在电脑上；硬件要产生并采样电压、处理数据、完成通信；软件要安排采样并发送结果。至于选哪款 MCU、使用什么驱动接口、是否需要操作系统，则取决于具体需求。

这就是本文希望建立的知识地图。之后学习电路、寄存器、外设或操作系统时，可以先问它在解决上述哪一个问题。下一步最适合做的，是找一个能实际看到结果的小任务，边实践边查清每个环节。
